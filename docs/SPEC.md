状態: **完成**  
最終正本化日: 2026-09-04  
最終ゲーム内容checkpoint: `1d0d05ae05b11d7954fdd6db63ae1889757505c5`

この文書は、現在の EcologicaLite v1R のゲーム仕様を示す正本である。HP、初期個体数、得点単価、能力効果量など、今後調整する可能性がある具体値は [`BALANCE.md`](./BALANCE.md) を正本とする。

## 1. 位置づけ

EcologicaLite v1R は、植物・草食・肉食の循環を観察しながら、能力選択によって生態系へ介入するブラウザゲームである。

プレイヤーは個体を直接移動させない。主な判断は、各取得機会でどの能力を選び、植物供給・草食繁殖・肉食捕食・生存・得点のどこを伸ばすかにある。

設計上は、厳密な永久均衡よりも次を優先する。

- 個体を追って見られること
- 繁殖・捕食・植物循環が盤面上で分かること
- 能力が噛み合うと生態系が繁栄すること
- 上手い選択ほど循環と得点の両方で報われること
- 相性の悪い能力組み合わせは許容するが、単体で平均的に不利な「罠能力」は作らないこと

## 2. ラン構造

- 1ランは **2 SET × 6 STAGE = 12 STAGE**。
- 各SET開始時に **SET能力を1つ**選ぶ。
- 各SETの STAGE 1〜5 終了後に、次STAGEへ向けて **通常能力を1つ**選ぶ。
- 1ランの能力取得機会は合計12回。
- SET 2 は新しい盤面・初期個体数から開始する。
- SET 1で取得した能力はSET 2へ引き継ぐ。
- 各SET内では、前STAGE終了時の生態系を次STAGEへ引き継ぐ。
- STAGE 3終了後に、そのSETで定めた後半用マップへ拡張する。実行中の密度を見て動的にサイズ変更する方式ではない。
- 全12 STAGE終了時の終了表示は **GAME SET** とする。

## 3. 生態系の基本

### 3.1 登場要素

- 植物
- 草食動物
- 肉食動物
- 死体
- 活動値

盤面の上下左右は接続したトーラス構造とする。

### 3.2 草食

- 一定Turnごとに上下左右へ移動する。
- 植物を食べるとHPを回復する。
- 摂食後に繁殖条件へ到達すると子を1体生む。
- HPが0になると自然死し、死体を残す。

### 3.3 肉食

- 草食より遅い周期で上下左右へ移動する。
- 草食を捕食するとHPを回復する。
- 捕食後に繁殖条件へ到達すると子を1体生む。
- HPが0になると自然死し、死体を残す。

### 3.4 HPと繁殖

- 草食・肉食とも最大HPを持つ。
- 初期HPは最大HPの一定割合から開始する。
- HPは移動の有無とは独立した周期で減少する。
- 摂食・捕食による回復で最大HPへ到達すると繁殖する。
- 通常繁殖後、親HPと子の基準HPは最大HPに対する一定割合へ設定する。
- 子HP強化能力は出生後の子へ加算する。

具体値は `BALANCE.md` を参照する。

## 4. 植物循環

植物供給には複数の経路を持つ。

### 活動由来

草食の摂食と肉食の捕食で活動値が増え、一定値に達すると植物を生成する。

### 死体由来

自然死した動物は死体となる。死体は一定期間残り、一定間隔で周囲への植物生成を試みる。

### 能力由来

植物周期、被食植物の再生、捕食の還元、一時投入などにより追加の植物循環経路を作れる。

植物供給は単一経路だけで完全循環を保証する設計にはしない。

## 5. 能力

### 5.1 SET能力

- 各SET開始時に1つ取得する。
- 同じラン中に取得したSET能力は以後も有効。
- 生態系全体の方向性を大きく変える。
- 現行能力は、時間、草食索敵・回避、植物循環、捕食還元、繁殖、肉食索敵などを扱う。

能力名と現行効果量は `BALANCE.md` を参照する。

### 5.2 通常能力

- STAGE間で取得する。
- 得点能力と生態系能力に分かれる。
- 通常の提示は **得点能力1枠 + 生態系能力2枠** の3択。
- 同一通常能力は原則最大3積み。
- 一時投入能力は取得時に即時効果を与える。
- 取得済み能力はSETをまたいで保持する。

## 6. 得点

得点源は6系統。

1. 植物摂食
2. 肉食捕食
3. 草食誕生
4. 肉食誕生
5. STAGE終了時の草食生存
6. STAGE終了時の肉食生存

基本式は次のとおり。

`項目得点 = 対象イベント数（生存はSTAGE終了時個体数） × 基礎点 × 能力倍率`

- 得点能力の重複効果は加算して倍率へ反映する。
- STAGE番号による人工的な得点倍率は設けない。
- 絶滅回避ボーナスは設けない。
- 高得点は、摂食・捕食・繁殖・生存が循環して増えた結果として自然に伸びることを目標とする。

現行基礎点と能力倍率は `BALANCE.md` を参照する。

## 7. 時間と再生

- 各STAGEは固定の基準Turn数を持つ。
- 基準表示速度と再生倍率を分離する。
- プレイヤーは **1× / 4× / 8×** を切り替えられる。
- 再生速度を変更しても論理Turnを飛ばさない。
- 一時停止、再開、速度変更はゲーム乱数を消費せず、同じ条件の結果へ影響しない。
- SET能力「時間延長」は各SET内でSTAGEが進むほど追加時間を増やし、次SETでは増加量をリセットする。

## 8. seedと再現性

ゲーム結果へ影響する乱数はmaster seedから決定論的に派生させる。

同じゲーム／ルール設定で、次が一致する場合は同じランを再現できることを基準とする。

- master seed
- 能力選択順
- ゲーム・ルール・RNG・設定バージョン

能力候補抽選とシミュレーション用乱数は用途別に分離する。UI操作によって乱数系列を変化させない。

### やり直し

- 同じseedでSET 1開始状態へ戻る。
- 盤面、得点、能力取得履歴、乱数状態を初期化する。
- 同じ能力を同じ順番で選べば同じ結果を再現する。

### 最初から

- 新しいseedを生成する。
- 新規ランとしてSET 1から開始する。

## 9. 分析データとCSV

内部では、画面表示より広い分析情報を保持する。

STAGE単位で少なくとも次を記録する。

- seed・version・config hash
- SET / STAGE
- マップ寸法・Turn数
- 提示された能力候補と選択能力
- 取得済み能力とstack数
- 植物・草食・肉食・死体の開始／終了／最小／最大
- 摂食・捕食
- 草食／肉食の出生・死亡
- 植物供給の発生源別集計
- 活動値
- 得点6項目の生値・倍率・項目別得点
- STAGE得点・累計得点
- 絶滅Turnなどの診断値

「結果コピー」は原則 **1 STAGE = 1行** のCSVを出力し、CSV単体をChat等へ貼って比較分析できる自己完結性を優先する。

画面に表示する項目を減らしても、分析用内部記録を同時に削らない。

## 10. UI共通方針

PC版とスマホ版は別ゲームではない。

- 同じゲーム状態
- 同じシミュレーション
- 同じデータ
- 同じ基本DOM・コンポーネント

を使用し、画面幅に応じて配置と寸法だけを変える。

### スマホ

基本順は、STAGE → 個体数・得点 → 盤面 → 操作 → グラフ／取得能力。

個体選択時は、動物アイコン、ID、現在HP、HPバーを表示する。取得済み能力はtapで効果説明を確認する。

### PC

中央に盤面、左にSTAGE・個体数／得点・グラフ、右に取得能力・個体HP・再生操作・リスタート操作を配置する3列構成を基準とする。

取得済み能力はhover/focusで効果説明を確認する。

## 11. ゲーム情報画面

EcologicaLiteのゲーム名を入口として、固定仕様を確認できる画面を開く。

表示階層は次の順。

1. ゲームガイド
2. 詳細データ
3. 内部仕様

この画面には、プレイごとに変化する現在値を載せない。

載せない例:

- 現在seed
- 現在個体数
- 現在得点
- 現在STAGE
- 今回取得した能力
- 選択中個体

固定仕様だけを表示する。

## 12. 正本と変更ルール

現在の正本は次のとおり。

- ゲーム仕様: `docs/SPEC.md`
- 調整値: `docs/BALANCE.md`
- 主要な変更理由・検証: `docs/DEVELOPMENT_LOG.md`
