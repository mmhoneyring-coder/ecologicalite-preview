# Balance diagnostic runner

EcologicaLite v1R の現行バランスを変更せず、能力選択の強さ・活躍時期・ビルド経路を診断するための runner。

## 目的

主に次を確認する。

- 終盤型能力が、活躍期間の短さに対して弱すぎないか
- 一時投入（植物+12 / 草食+2）を優先するだけで強くなりすぎていないか
- 逆に一時投入が選ぶ価値を失っていないか
- 初期SET能力から狙った方向へビルドを寄せられるか
- ビルドごとに12 STAGEの成長経路が変わるか
- 最終状態・最終得点がどう変わるか

最終状態が似ること自体は失敗条件にしない。経緯と最終結果を両方記録する。

## 方針

- `index.html` 内の現行 `v1r-runtime` を直接読み込む。
- 別実装の生態系ロジックを持たない。
- SET1能力は比較軸として固定する。
- 通常能力は実際の3択から選ぶ。
- SET2能力は実際に提示された候補から選ぶ。
- seedは全ビルド・全方針で共通にする。
- 数値調整・自動採用・自動PASS/FAILは行わない。

## 比較する通常能力方針

各SET1能力について、以下を同じseedで比較する。

1. 狙いビルド
2. 一時投入最優先
3. 一時投入なし
4. 得点能力優先
5. 混合基準

SET1能力は8種なので、標準30seedでは `8 × 5 × 30 = 1200` ランを実行する。

## 実行

Node.js 20+。

```bash
node tools/balance-diagnostics/runner.mjs --seeds=30 --out=artifacts/balance-diagnostics
```

軽い確認:

```bash
node tools/balance-diagnostics/runner.mjs --seeds=2 --out=/tmp/ecologicalite-balance-smoke
```

## 出力

- `SUMMARY.md`: 人間向け要約
- `summary.json`: 集計値・STAGE平均曲線・ビルド間経路距離
- `runs.csv`: 1ラン1行
- `stages.csv`: 1 STAGE 1行。ゲーム本体の分析列を保持
- `choices.csv`: 能力候補と選択履歴
- `runs.json`: 各ランの曲線・最終状態・能力取得情報

## 見方

### 終盤型

各SETのS1–3とS4–6、12 STAGEの平均得点曲線を見る。時間延長などは、序盤の平均だけで弱いと判断せず、後半の伸びと上振れ時の得点上限を見る。

### 一時投入

`一時投入最優先` と `一時投入なし` を `狙いビルド` と比較する。

- 一時投入最優先がSET能力を問わず一貫して強い → 万能化の疑い
- 一時投入なしが一貫して強い → 一時投入が弱すぎる疑い
- seed・ビルド・取得時期で価値が変わる → 選択肢として機能している可能性

### 狙ったビルド

`preferred_pick_rate` は、そのビルドの主要通常能力が候補に出た機会のうち、主要能力を取得した割合。候補運そのものは `choices.csv` で確認する。

### 経路と最終状態

`summary.json` / `SUMMARY.md` の経路差は、植物・草食・肉食の12 STAGE平均推移を正規化して比較する。最終差も別に記録するため、最終状態が近くても途中経過だけ異なるケースを確認できる。

## 注意

このrunnerの結果だけでバランス値を変更しない。問題が明確に見えた項目だけseed数を増やし、必要なら同seedで追加検証してから調整を検討する。
